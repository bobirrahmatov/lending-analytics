COVENANTS — RISK VIEW AND DAILY COMPARISONS

Presentation
- Upcoming Due Timeline and What needs attention exchange positions in coming-due analyses.
- Default desktop row: Aging Severity by Region takes 4/12 columns, Product Program takes 8/12.
- Severity uses stacked columns in the portfolio CCM style. Cartesian plots resize to the card's available height.
- Shared portfolio aging: 1–30, 31–45, 46–60, 61–90, >90. Missing aging remains explicit.
- Original covenant/region/activity/product/underwriter/frequency analyses and source fields remain.

Facility-level reporting
- Facility Covenant Risk assigns one highest-priority state per region + relationship ID + facility ID.
- Risk Watchlist shows past-due facilities, >90 facilities and data linkage exceptions. These counts overlap.
- Facility level register includes obligations, statuses, aging, ownership, source dates, match status,
  linked USD TFA/OSUC/outstanding/direct OS/contingent OS/unused commitment, classification, risk category,
  facility type, management status, commitment, ROTCE, pricing exceptions and maturity when supplied.
- Portfolio joins require exact composite identifiers and the same reporting date. Conflicting CA IDs,
  duplicate portfolio candidates and mixed covenant dates are excluded. There is no name/fuzzy join.
- A facility balance is attributed once, not once per covenant. Missing/non-USD balances are unavailable.
- The original four covenant KPI cards contain TFA and OSUC, facility/relationship counts, linkage coverage and daily variances. Expanded facility KPIs retain these measures.
  Unmatched exposure is not zero. Partial subtotals are labelled Linked; variance is withheld until both cohorts are fully linked.
- Default Covenant–facility links view keeps every source association: covenant number, relationship ID/name,
  facility ID, explicit banker name, TFA, OSUC, underwriter and join status. Facility view groups these links.
- A covenant number is NOT a unique association key. Monitoring item_id must incorporate source, obligation,
  relationship, facility and reporting cycle (or a source-native unique association key). Never deduplicate on covenant number.
- OSUC comes from the prepared portfolio osuc measure, not total_os. PAL regional rules remain upstream.
- Optional banker_name is supported in Monitoring and Portfolio. PAL-ETL exports Banker_Name from explicit
  Banker Name / Banker_Name / Banker / Relationship Manager columns. Map it to banker_name in the prepared workbook.
  Underwriter is never substituted for banker. Preserve the explicit field in Monitoring.xlsx and Portfolio.xlsx.
- The default preview is now a separately generated, explicitly synthetic aligned August 2026 scenario.
  ?covenants_source=local retains the original November 2024 example; ?covenants_source=workbook selects workbook examples.
  These original legacy examples do not have same-date portfolio matches. Production requires synchronized releases.
- Source coverage register exposes the covenant, activity and portfolio control rows. These are full-file
  controls, not filtered counts. EXCEPTIONS_ONLY does not describe all performing obligations.
- Past due is an operational exception, not proof of covenant breach or credit default.

Daily variance contract
- Covenant count, relationship count, facility count and chart-population badges compare the exact prior weekday.
  Monday compares with Friday. Holidays are not guessed; missing weekday snapshots remain unavailable.
- Both dates must reconcile to source controls, retain identical source IDs and coverage, and use identical filters.
- Absolute delta = current minus prior. Percentage = delta / prior. Zero prior displays New or No change.
- Chart badges explicitly describe the cohort total, not an individual bar/slice's change.
- Linked facility balance KPI variances remain unavailable without comparable facility balance history;
  covenant history must not be substituted for balance history.
- Activity charts compare consecutive maker months. If the current reporting month is incomplete, both
  periods stop at the same elapsed day (clamped to prior month end). Mixed report dates are unavailable.
  This is an event-volume comparison, not a daily change or clearance rate.

Retaining history without changing published data
The six shared runtime workbooks remain the default inputs. Retained covenant_history is optional.
The browser validates schema/bundle identity, row counts, complete snapshot controls, source counts,
unique date/key pairs and the full monitoring schema per snapshot. Invalid optional history disables
comparison; it does not substitute zeros or stop the current dashboard.

Run from the full package's tools directory, using validated prepared JSON releases (this utility does not parse XLSX workbooks):

python3 build_covenant_history.py \
  --current-manifest /path/current/credit-manifest.json \
  --prior-manifest /path/previous/credit-manifest.json \
  --output-dir /path/NEW-publication-folder \
  --release-id cov-risk-20261026 \
  --keep 32

The tool retains covenant rows AND full portfolio rows when the portfolio controls share the covenant reporting date.
The history payload has rows, snapshots (including optional portfolio_sources), and portfolio_rows. Each date
reconciles independently. Current and prior cohorts are joined to their own date-specific balances. TFA and
OSUC deltas = current unique-facility total minus prior unique-facility total; percentage divides by prior.
Retained portfolio data is carried forward and validated too. Reduce --keep if the attachment size is exceeded.
The tool writes a NEW complete release.
It refuses existing output directories, conflicting dates, mixed demo/live data, incorrect controls and >10MB files.
It does not upload or schedule anything. Upload every file from the new release, then its manifest LAST using
normal authorized Confluence publication. Never mix its new manifest with files from the older bundle.
Live comparisons never estimate missing prior values. The separate default demo intentionally supplies synthetic current and prior files for comparison; no production JSON was changed. See All_Pages_Data_Handoff.txt for the workbook and optional comparison-file contract.

ETL fidelity
PAL-ETL.html emits Report_Date and covenant dates in DD/MM/YYYY. That source contract is explicitly recognized.
Legacy workbook date values retain their existing month-first interpretation; prepared ISO dates are unchanged.
Original source fields are retained in record details and CSV; canonical aliases drive the displayed tables.
