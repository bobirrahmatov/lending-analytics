RESET, TABS AND RELATED-DATA RESPONSIVENESS
27 October 2026 · build bec4fba610d1

CONFIRMED CAUSES AND FIXES
1. Render disposed charts before awaiting sources. A newer partial update could
   cancel that render and leave the first chart destroyed. Pending widget IDs
   now merge; full updates take precedence; only the latest request commits.
2. Busy segmented controls discarded subsequent clicks. The latest intent now
   wins, with ownership of busy cleanup. Covenant/PAL intent updates before
   scheduling, so an older callback cannot overwrite Reset.
3. Related-data joins rescanned whole arrays for each historical record/event.
   Per-cohort indexes preserve exact date/entity/CA/ambiguity semantics.
4. Inline transitions built the same table multiple times. Only the visible
   table is built, with the related scope retained across view/dataset switches.
5. Reset left advanced column filters behind; it now clears complete table state.
   Unrelated chart updates preserve the register export and download state.
6. Missing optional enrichment was retried on every render. Its result is now
   remembered for the loaded release; a page reload retries enrichment.
