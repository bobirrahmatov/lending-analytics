Dashboard Excel data guide

Replace the synthetic sample rows with prepared source data. The dashboards read these Excel attachments directly. No JSON data files or manifest are required in workbook mode.

Upload and replace data

  1. Keep filenames, sheet names and headers exactly as supplied. The leading Facility and Covenants columns follow the LPTM PAL ETL output. CCM follows its dashboard sample schema. Trends follows the LPTM aggregate export. Activity, Insurance and Appraisals use explicit dashboard contracts; no unverified legacy column order is claimed.
  2. Replace data values in every relevant sheet. Keep identifiers as text, dates as YYYY-MM-DD text or real date-only Excel cells, amounts as numeric USD units, and flag fields as actual TRUE/FALSE booleans. PSE_non_PSE uses PSE/non-PSE; SFT_Facility uses Yes/No; Committed_Uncommitted uses Committed/Uncommitted. ROTCE is a decimal ratio, not a value multiplied by 100. No formulas, merged cells or subtotal rows in input data.
  3. Retain Metadata in every file. Set schema_version=2 and workbook_contract=1. Use one new bundle_id across the entire upload, including previous and history files. Keep each file's dataset and period values. Update rows and any auxiliary sheet row counts. is_demo must remain TRUE for samples; use FALSE only for approved real records.
  4. Sources_current.xlsx is the source-control workbook. It declares each source ID, domain, reporting date, coverage and row count. Reconcile it against all current obligations, facility records and events. Sources_previous.xlsx does the same for optional previous files. Reporting dates describe source observations, not the upload date.
  5. Upload the complete selected set to attachment page 3845862527. Upload Sources_current.xlsx last and then reload. Updates are not atomic: the loader rejects mixed bundle IDs instead of combining different releases. No live data is stored in browser storage.
  6. For live use, set allowSampleData:false in the dashboard macros. Remove or replace old sample comparison attachments too. A missing or invalid optional previous file makes that domain's comparison unavailable; it is never replaced with an estimated change. A malformed required current file reports an error.

Grain and comparison methodology

Current monitoring has one row per source obligation/association, relationship, facility and cycle. Facility Data has one row per valid facility snapshot. Keep stable item_id, facility_key, event_id and source_record_id values; do not replace them with Excel row numbers. Join only exact entity IDs with compatible reporting dates and CA context. Display names are not join keys. Unknown optional values remain blank; a true zero remains numeric zero.

Prepared flags such as action_required, critical, coming_due, pal_ca_expired and the PAL period fields remain explicit input columns. Populate them using your approved source rules and reconcile them to the dates/status fields. The loader does not guess missing business rules from names or upload dates. Legacy LPTM exports require the additional validation fields and Metadata supplied here before use.

Previous files use the same columns as their current counterparts. Their Metadata.period is previous, and their reporting dates are historical. Dashboard weekday deltas require the immediately preceding weekday with matching source coverage. An older or prior-month snapshot remains historical data and is not labelled as a weekday comparison.

Portfolio_Aggregated_History.xlsx contains one row per Report_Date + Region + Product_Program + Product_Sub_Program + Committed_Uncommitted + PSE_non_PSE. It is already aggregated. Never include a total row alongside detail groups, duplicate a group, or add balances across reporting dates. Keep facility/underwriter-only fields blank and comparison_ready FALSE. Trends sums measures within a date and uses the last supplied snapshot in the matching month for MoM/QoQ/YoY. Missing baseline or a zero denominator is unavailable. Distinct relationship/CA counts across groups can overlap and must not be added as portfolio-wide distinct counts.

Products are source values, not a fixed four-product list. SBL, Structured Lending, CRE, Partner Lending, Law Firm, RRE and additional programs are accepted consistently when their exact values match across relevant files.

Covenants_History.xlsx separates Data (covenant rows), Portfolio (same-date facility snapshots), Snapshots (unique complete dates), and Controls (counts by date/domain/source). No earlier snapshot is manufactured from today's data.

Metadata fields

All files have a key/value Metadata sheet. rows counts Data records, excluding the header. Facility files also declare ca_rows and maturity_rows. Covenant history declares portfolio_rows, snapshots_rows and controls_rows. Keep zero-row sheets with their headers and a zero count. All listed columns must exist; “blank allowed” below refers to cell values, not permission to omit a header. Headers may move because mapping is by name, but the supplied ordering follows LPTM where verified.
