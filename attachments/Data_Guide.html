Dashboard Excel data guide

Replace the synthetic sample rows with prepared source data. The dashboards read these Excel attachments directly. No JSON data files or manifest are required in workbook mode. Sources_current.xlsx and Sources_previous.xlsx are not used.

Upload and replace data

  1. Keep filenames, sheet names and headers exactly as supplied. Covenants follows the original Covenants dashboard and Covenants_current.xlsx source headers. Activity follows Covenants_Activity_Report.xlsx (Maker Date and Covenant Compliance), delivered under Activity_current.xlsx. Insurance and Appraisals each use an independent domain contract, not LPTM. Only Facility follows the LPTM facility export; CCM follows its CCM schema and Trends follows the LPTM aggregate export. Insurance/Appraisal legacy source-file column order has not been verified; use the exact supplied domain template.
  2. Replace data values in every relevant sheet. Keep identifiers as text, dates as YYYY-MM-DD text or real date-only Excel cells, amounts as numeric USD units, and flag fields as plain Yes/No text (no checkboxes or TRUE/FALSE cells). PSE_non_PSE uses PSE/non-PSE; SFT_Facility uses Yes/No; Committed_Uncommitted uses Committed/Uncommitted. ROTCE is a decimal ratio, not a value multiplied by 100. No formulas, merged cells or subtotal rows in input data.
  3. Retain Metadata in every file. Set schema_version=2 and workbook_contract=2. Use one new bundle_id across the entire upload, including previous and history files. Keep each file's dataset and period values. Update rows and any auxiliary sheet row counts. is_demo must remain Yes for samples; use No only for approved real records.
  4. Source filenames, IDs, domains and coverage are fixed in the application. There are no Sources workbooks to maintain. Reporting dates come from each sheet’s As Of Date / Report_Date rows, never the upload date. A source sheet must have one reporting date. For a zero-row sheet only, supply as_of_date as YYYY-MM-DD text in Metadata because no row date exists.
  5. Upload the complete selected set to attachment page 3845862527. Upload previous files first, then all current files and selected history files; upload Facility_current.xlsx last and then reload. Updates are not atomic: the loader rejects mixed bundle IDs instead of combining different releases. No live data is stored in browser storage.
  6. For live use, set allowSampleData:false in the dashboard macros. Remove or replace old sample comparison attachments too. A missing or invalid optional previous file makes that domain's comparison unavailable; it is never replaced with an estimated change. A malformed required current file reports an error.

Weekly refresh

  1. Put the previous reporting snapshot in each _previous file and the new snapshot in its matching _current file. Keep the exact filenames and headers. As Of Date records the reporting date; Maker Date remains the individual Activity event date.
  2. Update Metadata row counts and period=current/previous. Give the entire upload one new bundle_id, including optional history. Keep flags as Yes/No text. Source IDs and domain mappings stay fixed and need no weekly edits.
  3. Upload the complete set, with Facility_current.xlsx last, and reload. Fixed-name replacements are not atomic; mixed bundle IDs are rejected while uploads are incomplete.

Grain and comparison methodology

Current monitoring has one row per source obligation/association, relationship, facility and cycle. Facility Data has one row per valid facility snapshot. Keep stable item_id, facility_key, event_id and source_record_id values; do not replace them with Excel row numbers. Join only exact entity IDs with compatible reporting dates and CA context. Display names are not join keys. Unknown optional values remain blank; a true zero remains numeric zero.

Prepared flags such as action_required, critical, coming_due, pal_ca_expired and the PAL period fields remain explicit input columns. Populate them using your approved source rules and reconcile them to the dates/status fields. The loader does not guess missing business rules from names or upload dates. Raw source exports require the additional validation fields and Metadata supplied here before use.

Every snapshot comparison uses its matching _current and _previous workbooks. The application constructs source controls from the fixed mapping and validated workbook contents. Missing previous files remain unavailable even if historical records or consolidated Trends data exist.

Previous files use the same columns as their current counterparts. Their Metadata.period is previous, and their reporting dates are historical. Weekly deltas compare the supplied current and previous reporting dates with matching configured coverage. The previous date must be strictly earlier; it need not be the previous weekday or exactly seven days earlier. Both dates are displayed, so a skipped reporting week is not silently labelled as one-week growth.

Portfolio_Aggregated_History.xlsx contains one row per Report_Date + Region + Product_Program + Product_Sub_Program + Committed_Uncommitted + PSE_non_PSE. It is already aggregated. Never include a total row alongside detail groups, duplicate a group, or add balances across reporting dates. Keep facility/underwriter-only fields blank and comparison_ready No. Trends sums measures within a date and uses the last supplied snapshot in the matching month for MoM/QoQ/YoY. Missing baseline or a zero denominator is unavailable. Distinct relationship/CA counts across groups can overlap and must not be added as portfolio-wide distinct counts.

Products are source values, not a fixed four-product list. SBL, Structured Lending, CRE, Partner Lending, Law Firm, RRE and additional programs are accepted consistently when their exact values match across relevant files.

Covenants_History.xlsx separates Data (covenant rows), Portfolio (same-date facility snapshots), Snapshots (unique complete dates), and Controls (counts by date/domain/source). No earlier snapshot is manufactured from today's data.

Metadata fields

All files have a key/value Metadata sheet. rows counts Data records, excluding the header. Facility files also declare ca_rows and maturity_rows. Covenant history declares portfolio_rows, snapshots_rows and controls_rows. Keep zero-row sheets with their headers and a zero count. All listed columns must exist; “blank allowed” below refers to cell values, not permission to omit a header. Headers may move because mapping is by name, but the supplied ordering follows each verified owning source.
