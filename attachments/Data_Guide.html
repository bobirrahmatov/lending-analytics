Dashboard Excel data guide

The dashboards read Excel data sheets directly. There are no Metadata tabs, workbook settings, bundle IDs, manually maintained row counts, JSON data files or Sources workbooks to upload. The included example rows are synthetic.

Install this update

  1. Upload the matching JavaScript, CSS, images and Data_Guide.html from attachments/ to Confluence attachment page 3845862527. Replace the native HTML macros using pages/. Each Page.js and HTMLPage.js pair must come from this same build. Reload after the upload; hard-refresh if old scripts remain cached.
  2. Use the new workbooks with data sheets only, or delete Metadata from your existing workbooks. Existing contract-3 underscore headers, including the old PAL_ aliases, remain accepted. Any old Metadata sheet left in a workbook is ignored. The new loader requires no file-level settings or hidden replacement fields.
  3. For sample preview, the supplied macros set sampleData:true and allowSampleData:true. When using your real data, change both to false once. This setting declares whether the uploaded rows are examples; without a per-workbook marker the dashboard cannot automatically establish sample/live provenance. Replace every sample row and sample comparison file before switching to live use.

Weekly updates

  1. Put the previous reporting snapshot in each _previous file and the new snapshot in the matching _current file. Keep the supplied filenames, data-sheet names and column headers. No weekly settings edits are needed.
  2. Update every relevant data sheet. Report_Date is the reporting snapshot date; Maker_Date remains the Activity event date. Nonempty current source sheets must all have the same Report_Date as Facility_current.xlsx / Data. History workbooks intentionally contain several dates.
  3. Row counts are calculated from nonblank records automatically. Empty monitoring or Activity populations can retain just the headers. Their date comes from the Data sheet of the matching Facility_current.xlsx or Facility_previous.xlsx. Each Facility Data sheet used as a date anchor must contain at least one dated record. An empty previous source without a dated previous Facility snapshot is unavailable; it never inherits the current date.
  4. Upload the previous files, then current/history files, with Facility_current.xlsx last. Reload only after the upload is complete. Replacements are not atomic: differing current reporting dates are rejected, but partial uploads carrying the same reporting date cannot be identified from the data alone. Compare your source export counts before upload.

Data rules

Use the exact underscore headers listed below. Keep identifiers as text to preserve leading zeros; dates as YYYY-MM-DD text or date-only Excel cells; amounts as numeric USD units; and flags as plain Yes/No text. PSE_Non_PSE uses PSE/non-PSE and Committed_Uncommitted uses Committed/Uncommitted. ROTCE is a decimal ratio. Do not include formulas, merged cells, subtotal rows or duplicate record keys.

All listed columns must exist. Blank allowed refers to values, not missing headers. Columns can move because the loader maps by name, but the supplied order follows each verified owning source. Products are source values, not a fixed list: SBL, Structured Lending, CRE, Partner Lending, Law Firm, RRE and additional programs are supported.

Source ownership and methodology

Covenants follows the original Covenants dashboard; Activity follows Covenants_Activity_Report.xlsx under the agreed Activity filenames. Neither is an LPTM feed. Insurance and Appraisals have independent contracts; their original export ordering has not been verified, so use these templates. Facility and consolidated Trends follow LPTM mappings; CCM follows its CCM schema.

Facility Data has one row per valid facility snapshot. Monitoring retains each source obligation/association and cycle. Preserve Item_ID, Facility_Key, Event_ID and Source_Record_ID. Join only compatible reporting dates and exact identifiers/CA context. Do not infer identity from names or count the same facility balance once per covenant link.

Comparisons read matching _previous files. The previous Report_Date must be strictly earlier than the current date; weekly and skipped-week intervals are supported and both dates are displayed. Missing or invalid previous data makes the affected comparison unavailable. It is never estimated or substituted from consolidated Trends.

Portfolio_Aggregated_History.xlsx contains one row per Report_Date + Region + Product_Program + Product_Sub_Program + Committed_Uncommitted + PSE_Non_PSE. Do not mix total rows with detail groups or sum balances across dates. Keep facility/underwriter-only fields blank and Comparison_Ready No. Trends uses the last supplied snapshot in the corresponding month for MoM/QoQ/YoY; missing baselines and zero denominators are unavailable. Distinct relationship/CA counts across groups may overlap and must not be added as portfolio-wide distinct counts.

Covenants_History.xlsx retains Data, Portfolio, Snapshots and Controls. These are dated historical records and their source counts/completeness, not workbook Metadata. They support validation of historical drill-downs. Do not manufacture earlier records from the current snapshot.
