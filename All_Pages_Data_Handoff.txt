LENDING ANALYTICS — DASHBOARD DATA HANDOFF
27 October 2026

PURPOSE AND SCOPE
Lending Analytics is a Confluence dashboard for everyone with access to the wcs
space. It adds no login, access request, entitlement registry or administration
pages. Native Confluence page and attachment permissions remain authoritative.
The landing page introduces 11 dashboards. Portfolio Overview is the financial
view; Underwriter Summary is the high-level action and ownership view.

Open Data_Integration_Kit/index.html for complete field dictionaries, source
lineage, primary keys, exact joins and examples. Its page-source-map.json includes
native page IDs and every dashboard’s fixed-name file dependencies. Start_Here.html
is a local installation guide; it is not another end-user Confluence page.

Upload the six prepared workbooks from excel/runtime/ to attachment page

All pages read these shared files. Do not maintain separate copies per dashboard.
A covenant can link to several facilities or relationships; preserve each source
association using item_id. An event is not an obligation. A facility ID is not a
policy, appraisal or approval-cycle key. Source owners must supply those identities.
Raw upstream workbooks require mapping to the canonical Data/Metadata contract;
the dashboard does not perform a staging database import.

Sources.xlsx and Monitoring.xlsx participate in shared startup validation.

Lending Analytics downloads no financial records. The retained trends URL is only
a Portfolio compatibility route, not another navigation page. Sources remains a
dataset; no Sources page is installed.

RELATED DATA AND COUNTING RULES
Use exact region, relationship_id, facility_id and reporting-date matches.
Supplied CA IDs must agree. Do not join on display names, owner names or fuzzy text.
Keep unmatched, ambiguous, date-conflicting and non-USD records visible; attributed
amounts are unavailable. Deduplicate TFA/OSUC at the valid facility-snapshot grain
before summing. Partial matched totals are Linked exposure, not complete exposure.
Never sum balances over reporting dates, or sum/average relationship ROTCE ratios.

Documents need explicit matching entity keys and dates for entity-specific evidence.
The supplied general landing-page document is a reference, not facility evidence.
Facility maturity dates alone cannot establish a pending credit authorization.
Maker Date describes a recorded activity event; Deferred Date describes the deferred
due date. Deferred events do not imply clearance.

OPTIONAL COMPARISONS
credit-previous.json carries the reconciled prior snapshot.
credit-covenant-history.json carries retained covenant and facility snapshots.
Declare each supplied file in credit-manifest.json with the correct row count.
Every payload and workbook must share the current bundle_id. Keys repeat across
periods by design; uniqueness is evaluated within the appropriate dated snapshot.
Daily changes require the exact previous weekday, consistent source coverage and
matching filters. A missing period is unavailable. Historical detail cannot be
reconstructed from current facilities. The standalone JSON validators and history
utilities in tools/ are optional; no database integration is required.

PUBLICATION AND CACHE
Prepare and validate one coherent set, upload workbooks and optional comparisons
first, then credit-manifest.json last. Filenames remain stable without version or
query suffixes. Every attachment and archive must be below 10,000,000 bytes.
Replacing multiple attachments is not atomic. Mixed identities/counts are rejected.
An open page retains its already-validated snapshot; reload obtains current files.
Financial records are not persisted in browser storage. Native attachment errors
or sign-in responses cannot fall back to cached financial data.

Included workbooks are synthetic samples with is_demo=true. Supplied sample macros
allow them explicitly. For live use, set allowSampleData:false and use approved
records marked is_demo:false. Never relabel samples as live or replace live files
with examples. Standalone validate_release.py checks JSON, not XLSX workbooks.

USER JOURNEY
Page filters affect supported page populations. Local chart and table drilling
stays in one full-row widget with visible breadcrumbs; unrelated charts keep their
scope. Expanded analyses open in one modal with relevant KPIs, analytical charts
and supporting records. Close restores the originating dashboard and focus.
Detailed tables share search, column filters/sorting, a 10-row default and exports
of all matching records. Related tables retain their original record grain.

VERIFICATION
Run npm test for shared logic changes and npm run package for release artifacts.
Local fixtures validate calculations, typed workbook loading, source/key matching,
filters, chart/table drill journeys, Reset/tab scheduling and lifecycle handling.
They do not establish live Confluence rendering or real source completeness.
Recorded 75,000-row JSON processing excludes network transfer and is not a
five-second Excel loading guarantee. Proposed business thresholds require source
owner approval before use as production policy.
